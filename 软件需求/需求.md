# 一、概述
## 1.1 产品概述及目标
### 1.1.1 背景介绍
基于公司现有项目、产品的工作流，实现一个可以辅助项目管理的自动化助手，解决多项目、多产品公司内部的项目管理混乱和困难问题。
### 1.1.2 产品概述
能够自动根据已有的项目过程数据自动生成如下信息，方便项目管理人员和各参与人员直观、便捷的查看、接收项目动态等功能。：
- 项目进度：总体进度和各个阶段的进度
- 项目各阶段的当前状态
- 各阶段的卡点和责任人
- 项目风险自动提示
- 项目报表（日报、周报、月报、季报、年报等）
- 各阶段的文档齐套性状态
- 所有产品和项目的映射关系
- 各个阶段对应的软硬件资料链接便捷跳转等

## 2.2 产品需求描述
能够自动根据已有的项目过程数据自动完成如下功能：
- 项目进度(甘特图)
- 可以查看项目的各阶段当前的卡点和对应责任人信息
- 可以直观便捷的查看、查询产品、项目、用户三者的映射关系，可以通过三者相互查询对应关系（因为一个产品会应用到不同的项目、不同的客户，同时同一个项目可能需要多个产品组合对外提供最终交付集合，同一个客户可能对应多个项目、多个产品等），比如可参考Obsidian和Xmind的关系图谱设计思想，实现可以：
    - 从项目角度快速查看产品组成；
    - 从项目角度快速查看对应的客户信息；
    - 从产品的角度查看应用到了哪些项目；
    - 从产品的角度查看应用到了哪些客户；
    - 从客户的角度查看涉及到哪些项目；
    - 从客户的角度查看购买过哪些产品；
- 每个项目对应的产品的软硬件交付资料可以通过链接快速跳转查看（这些信息目前已经有了，但是分散在各个系统中，比如硬件放在NAS上、软件放在Gitlab上，当然如果有必要，可以要求硬件也提交到Gitlab上来跟踪，具体以规范性、易实现性、易管理性为原则，可以反向指定规则来要求）：
    - 硬件常见输出材料：
        - 原理图
        - Layout
        - BOM清单
        - 硬件采购清单
        - 中间件清单
        - 软硬件交互文档
        - 结构交互文档；
        - 硬件调试记录；
        - BOM定稿；
    - 软件资料：
        - Gitlab仓库源码链接；
        - 最新版本发布的路径；
        - 交付文档链接等；
- 每个产品可以对应的所有项目的软硬件资料也可以通过前述方法快速查询；
- 可以查看各项目的产品交付状态：应交付总数、已交付数量、已交付编号、交付时间、剩余未交付数量及原因；
- 由于存在一些项目是老客户的直接采购，这种项目就不需要完成的研发流程，因此需要区分研发项目和生产项目，这两种项目的流程会有所差异：比如生产项目不需要硬件、软件的需求分析、开发调试等流程了，只需要确认BOM清单、采购、生产、结构安装、测试交付即可。
- 项目的数据统计报告（bug统计、gitlab提交统计）
- 此系统的项目进度信息，主要以如下信息为源来自动判别对应项目阶段的最终执行结果：
    - 禅道的对应项目的各项任务执行结果和任务描述信息中的特定格式，比如：
        - 禅道中的任务结果必须是“已完成”；
        - 任务描述信息中必须包含关键字【同意】、【不同意】等，这个根据不同任务可能会有不同的规则要求）
    - Gitlab有对应的发布界面，且满足必要的要素要求，满足公司的规范（该规范可能随时更新，以`http://192.168.0.100/standardization/rd/standard/git-rel`的README说明为准；
    - 注意：如果禅道的任务状态是已完成，但是没有对应的输出件（禅道、gitlab），则需要在此系统中也以告警的形态呈现，方便项目管理人员关注；

# 四、流程说明
整个项目进度需要包含项目全流程的状态监控（每个过程都要求有前述必须的输出件），过程主要包括如下流程(按项目运行顺序)（每个项目的负责人通过【人力岗位】来描述）：
- 售前：
    - 需求导入：输入技术需求书；【销售及售前】
    - 需求评估（各个维度可根据权重打分决定最终可行性），输出：
        - 技术可行性报告——技术能否搞定（技术、周期）【CTO】；
        - 商务可行性报告——投入能否赚钱；【CEO】
        - 综合可行性报告——根据权重评分得出初步结论；【CEO】
    - 项目立项决策，输出：
        - 立项决议书（结论及原因，项目交付节点)；【销售及售前】
        - 转研发项目or转生产项目，并创建售前转研发的交接任务：通知项目经理开始立项；【CTO】
- 项目立项：
    - 创建禅道项目【项目经理】【输出：创建好对应的禅道项目】
    - 实施方案草案编写；【CTO】【输出：实施方案草案】
    - 项目启动会：【项目经理】【输出：人力资源排布和项目周期计划表（可以放在一个表格中）、禅道项目中的阶段创建（责任人和周期）】
        - 人力资源排布（包含各方向责任人信息，如下为举例）；
            - 硬件开发：USER_1；
            - 硬件测试：USER_11;
            - 结构设计及装配： USER_2；
            - BSP开发: USER_3；
            - 软件开发: USER_4；
            - 测试交付: USER_5；
            - 采购： USER_6；
            - 质量：  USER_7;
        - 项目周期计划；

            - 结构：2026.04.01-2026.04.10
            - BSP：2026.04.01-2026.04.15

    - 项目编号示例：PE0444、PE0406；
    - 用户简称示例：CDYA、YZYA、CDLY：

- 项目列表的第一个标签`RD`/`SC`改为项目编号，比如`PE0444`，项目信息显示为：`项目属性(客户简称)`的形式；
