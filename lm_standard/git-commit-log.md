## 1、Git Commit Log 规范
### 1.1 概述
规范的 commit log 有助于团队协作、代码审查和版本管理。本文档定义了标准的 commit message 格式。

### 1.2 Commit Message 格式
每个 commit message 应包含三部分：Header、Body 和 Footer。格式如下：
```
必填->   <type>(<scope>): <subject>

选填->   <body>

选填->   <footer>
```
#### 1.2.1 Header（必需）是单行摘要，包含三个部分：type、scope 和 subject。
##### type（类型）
* feat: 新功能
* fix: 修复 bug
* docs: 文档更新
* style: 代码格式调整（不影响功能）
* refactor: 代码重构（非功能修改）
* test: 测试相关
* chore: 构建过程或辅助工具变动
* perf: 性能优化
* ci: CI/CD 配置变更
##### scope（范围，可选）说明影响范围，如模块、组件或文件名：
* sata: sata模块
* app: 用户模块
* api: API 相关
* ui: 界面组件
* deps: 依赖更新
##### subject（主题）
* 首字母小写
* 不加句号
* 长度建议不超过 50个 英文字符
##### Header编写示例
```
feat(auth): 新增存储登录登录支持
fix(api): 修复分页问题
docs(readme): 更新安装步骤
```
#### 1.2.2 body（可选）
详细描述变更内容(使用空行与 Header 分隔)：
* 说明「为什么」进行此变更
* 与之前行为的对比
* 使用的算法或方法
* 每行不超过 72 英文字符
```
feat(user): 新增用户验证功能

- 添加个人资料上传组件
- 实现支持 Markdown 的简介字段
- 添加用户输入验证
- 更新用户模型以包含新字段
```

#### 1.2.2 footer（可选）
包含以下信息（使用空行与body分隔）：
* 关联 issue
* 使用关键字关闭或引用 issue：
```
bug#205
bug#256,257
task#300
task#301,302
```

## 2、完整示例
### 示例 1：功能添加
```
feat(payment): 新增QPSK信号处理功能

- 集成QPSK时域信号显示功能
- 添加数据错误校验恢复功能
- 创建QPSK星座图显示页面
- 更新QPSK 解调BIT流显示

bug#205
bug#256,257
task#300
task#301,302
```
### 示例 2：Bug 修复
```
fix(database): 修复数据库连接超时问题

此前，数据库连接在高负载情况下会在 30 秒后超时。
本次变更将超时时间增加至 120 秒，并添加连接池功能。

- 实现最大 20 个连接的连接池
- 为查询失败添加重试逻辑
- 更新配置文档

bug#205
bug#256,257
task#300
task#301,302
```

### 示例 3：代码重构
```
refactor(auth): 将自研文件系统替换为exfat文件系统

- 将非标的自定义格式文件系统改为标准exfat文件系统
- 添加kernel中的exfat从内核摘出单独编译
- 屏蔽内核exfat驱动
- 移除废弃的中间转换层代码

重大变更: 所有和fpga交互的寄存器被重新定义，fuse文件系统将
被剔除出源码库，采用标准的NFS或者SAMBA支持老的业务；
```

## 3、bug和task格式必须按照以下格式填写
**注意：**
* 可以只写一个bug或者task编号，一次解决多个问题才填写多个bug或者task
* 按照该格式填写后,禅道系统的任务或者BUG关联到提交记录,在禅道统计页面可以统计出提交次数
* 按照附 图1 设置禅道账户以关联GIT提交；
```
bug#205
bug#256,257
task#300
task#301,302
```
